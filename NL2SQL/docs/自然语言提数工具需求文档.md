# 自然语言提数工具需求文档

## 1. 项目背景与目标

### 1.1 背景
基于对 7/24 Office AI Agent 项目的学习，希望实现一个专注于**数据查询场景**的智能体，用于通过自然语言查询 SR 系统的数据。

### 1.2 目标
- 让非技术人员通过自然语言获取数据
- 降低数据查询门槛，提升效率
- 保证查询准确性和数据安全性

## 3. 功能需求

### 3.1 核心功能

#### 3.1.1 自然语言查询
- 用户输入自然语言描述数据需求
- 系统解析意图并生成 SQL
- 执行查询并返回格式化结果

**示例交互：**
```
用户：查一下上个月各地区的销售额
系统：正在为您查询 2024-02-01 至 2024-02-29 各地区销售额...
      [结果表格]
      需要我生成趋势图吗？
```

#### 3.1.2 澄清机制
当信息不足时，主动询问用户：

| 缺失信息 | 澄清示例 |
|---------|---------|
| 时间范围 | "您想查询哪个时间段的数据？" |
| 指标不明确 | "您关注的指标是销售额、订单数还是销量？" |
| 维度未指定 | "需要按地区、产品还是时间趋势查看？" |
| 筛选条件 | "需要筛选特定品类或客户类型吗？" |

#### 3.1.3 Schema 智能匹配
- 基于用户查询语义，自动匹配相关数据表
- 字段别名识别（如"业绩"映射到"order_amount"）
- 多表关联自动推断

#### 3.1.4 SQL 生成与验证
- 自动生成标准 SQL（SELECT 语句）
- 安全校验：禁止 DML 操作（UPDATE/DELETE/DROP 等）
- 表白名单校验
- 自动添加 LIMIT 限制

#### 3.1.5 结果格式化
- 表格展示
- 自然语言总结
- 图表推荐（柱状图、折线图、饼图等）
- 异常数据标注

### 3.2 三层记忆系统

#### Layer 1: 会话历史（短期记忆）
- 存储最近 N 轮对话（默认 20 轮）
- 支持上下文连贯的多轮查询
- 存储格式：SQLite / JSON 文件

**示例：**
```
用户：查一下北京的数据
系统：[返回北京数据]
用户：那上海呢？  ← 系统理解"那"指代相同查询条件
```

#### Layer 2: 长期记忆（LLM 压缩）
- 自动提取用户查询偏好和常用模式
- 存储内容：
  - 常用查询模板
  - 字段别名映射（用户习惯用语）
  - 关注的业务指标

**存储结构：**
```json
{
  "type": "query_pattern",
  "user_id": "user_123",
  "pattern": {
    "name": "月度销售报表",
    "dimensions": ["month", "region"],
    "metrics": ["销售额", "订单数"],
    "default_time_range": "最近30天"
  },
  "created_at": "2024-01-15"
}
```

#### Layer 3: 向量检索（LanceDB）
- 语义检索相似的历史查询
- Schema 向量化，快速匹配相关表
- 查询案例库检索

### 3.3 自修复机制

#### 3.3.1 每日自检
- 检查查询成功率
- 统计慢查询
- 检查数据同步状态

#### 3.3.2 会话健康诊断
- 检测长时间未关闭的会话
- 清理过期会话数据

#### 3.3.3 错误日志分析
- 记录 SQL 生成失败案例
- 分析常见错误类型
- 自动优化 Prompt

#### 3.3.4 失败自动通知
- 查询失败时通知管理员
- 每日发送健康报告

## 4. 数据安全需求

### 4.1 查询安全
- **只读模式**：仅允许 SELECT 语句
- **表白名单**：只能访问授权的表
- **行级权限**：根据用户角色限制数据范围
- **敏感字段脱敏**：如手机号、身份证等

### 4.2 数据保护
- 不存储业务数据，仅存储查询逻辑
- 查询日志审计
- 敏感操作二次确认

---

## 5. 非功能需求

### 5.1 性能要求
- 简单查询响应时间 < 3 秒
- 复杂查询响应时间 < 10 秒
- 支持并发用户：50+

### 5.2 可用性要求
- 服务可用性：99.5%
- 支持优雅降级（LLM 不可用时返回提示）

### 5.3 扩展性要求
- 支持接入新的数据源
- 支持自定义查询模板
- 插件化工具系统

## 6. 接口设计

### 6.1 WebSocket API

#### 连接建立
```javascript
// Client → Server
ws.connect('/ws/chat?user_id=xxx&session_id=yyy')
```

#### 发送消息
```javascript
// Client → Server
{
  "type": "query",
  "message": "查一下上个月的销售额",
  "context": {} // 可选上下文
}
```

#### 流式响应
```javascript
// Server → Client
// 1. 意图识别结果
{ "type": "intent", "data": { "time_range": "上月", "metric": "销售额" } }

// 2. 需要澄清
{ "type": "clarify", "data": { "question": "需要按地区查看吗？" } }

// 3. SQL 生成
{ "type": "sql", "data": { "sql": "SELECT ...", "explanation": "查询上月销售额" } }

// 4. 查询结果
{ "type": "result", "data": { "rows": [], "summary": "总计销售额 100万" } }

// 5. 完成
{ "type": "done" }
```

### 6.2 REST API

| 接口 | 方法 | 说明 |
|-----|------|------|
| /api/schema | GET | 获取数据 Schema |
| /api/sessions | GET/POST | 会话管理 |
| /api/queries/history | GET | 查询历史 |
| /api/health | GET | 健康检查 |
