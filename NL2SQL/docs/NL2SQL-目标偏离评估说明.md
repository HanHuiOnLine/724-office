# NL2SQL 目标偏离评估说明

## 1. 文档信息
- 版本：v1.0
- 评估日期：2026-04-24
- 评估对象：`NL2SQL` 当前项目（以 Phase 1-4 优化交付为主）
- 结论摘要：项目整体未偏离“自然语言提数”核心目标，但在“数据最小化、真实环境验收闭环、非功能指标达标证明”上存在阶段性偏离。

## 3. 总体判定
1. 核心目标（自然语言到可执行 SQL、主链路稳定、复杂查询能力、安全治理）总体对齐，未出现方向性偏离。
2. 偏离主要体现在“验证闭环与治理深度”而非“技术路线错误”：
   - 有能力但未在真实环境完全验收
   - 有机制但默认未开启或仍处灰度
   - 有要求但缺量化达标证据
3. 偏离等级：中低（可控），当前可判定为“可上线灰度、未达最终完工态”。

## 4. 目标对齐评估（按需求文档主目标）
| 需求目标 | 当前状态 | 判定 |
|---|---|---|
| 让非技术人员通过自然语言获取数据 | NL2SQL 主链路、澄清机制、SSE 交互链路已可用；澄清断链批次 C 已补老前端兜底 | 对齐 |
| 降低数据查询门槛、提升效率 | Schema 召回与表排序优化已落地，回归脚本体系已建立；但复杂查询端到端在真实 LLM 环境的验证仍有缺口 | 基本对齐 |
| 保证查询准确性和数据安全性 | SQL 验证、LIMIT、脱敏、审计、RLS 改写能力已实现；但 RLS 默认未开启且真实方言采样未完成 | 部分对齐 |

## 5. 主要偏离项（按优先级）

### 5.1 P0（应优先收敛）
1. 真实环境验收闭环不足：
   - `test-executeQuery.js` 依赖 `SR_DATABASE_URL_TEST`
   - `test-regression-complex.js` 依赖 `LLM_API_KEY`
   当前环境均为 skip，导致“真实 SR + 真实 LLM”闭环证据不足。
2. 数据最小化要求存在冲突：
   需求文档要求“不存储业务数据，仅存储查询逻辑”；但 Phase 1 交接记录 `query_history.result` 会保存列信息及前 20 行样本，存在策略偏离与合规风险。

### 5.2 P1（应纳入下一阶段里程碑）
1. 行级权限（RLS）默认关闭（`FF_RLS_ENFORCEMENT=false`），且尚未完成 SR 真实 SQL 样本采样验证。
2. “失败自动通知管理员”在需求中明确，但目前文档证据以报表/日志为主，未见明确通知通道闭环（如 IM/邮件/Webhook）。
3. 性能与可用性目标缺量化达标证据：
   - 简单查询 <3 秒、复杂查询 <10 秒
   - 并发 50+
   - 可用性 99.5%
   当前未见系统化压测与SLA报表。

### 5.3 P2（可随版本演进收敛）
1. 接口设计层面需求以 WebSocket 为主示例，现阶段实现与验证以 SSE 为主，虽然技术选型不冲突，但文档与实现表述不一致。
2. 结果可视化、异常数据标注等前端体验项在本轮优化中不是主范围，完成度需单独核验。

## 6. 未偏离且完成度高的方面
1. 核心引擎闭环：真实查询执行链路、SSE 错误反馈、query_history 主流程写入。
2. 准确率主链路：候选表召回与统一排序（ranker）替代硬截断，LIMIT 双层兜底。
3. 安全治理：Prompt 脱敏日志、结果脱敏规则、审计字段扩展、RLS 改写能力。
4. 架构治理：`nl2sqlEngine.js` 拆分为 5 个职责模块，对外契约保持兼容。
5. 质量保障：测试聚合器与分阶段脚本齐备，Phase 3/4 自动化回归稳定。

## 7. 偏离成因判断
1. 属于“阶段性取舍”而非“方向错误”：优先打通可用闭环，再补足治理深水区。
2. 现有偏离与 Phase 4 文档中遗留 TODO 基本一致，风险已被识别并可追踪。
3. 主要短板在“真实环境验证与运营化指标”，不是核心代码路径失效。

## 8. 收敛建议（建议作为 Phase 5 验收前置）
1. 补齐两项端到端强依赖验证：
   - 配置 `SR_DATABASE_URL_TEST` 跑通真实库执行回归
   - 配置 `LLM_API_KEY` 跑通复杂查询端到端回归
2. 完成数据最小化整改：
   - 将 `query_history.result` 从“样本行存储”调整为“结构化摘要/哈希”
   - 增加可配置留存与脱敏策略
3. 完成 RLS 灰度上线前验证：
   - 用历史 SQL 样本做 `injectTenantFilter` dry-run
   - 明确拒绝率阈值与回滚策略
4. 建立非功能指标验收基线：
   - P95 时延、并发、成功率、可用性
   - 固化到日报/周报与发布门禁
5. 补全失败自动通知链路：
   - `selfRepair` 报告输出接入告警通道（邮件/IM/Webhook）

## 9. 最终结论
截至 2026-04-24，项目与《自然语言提数工具需求文档》的核心目标总体一致，未发生路线级偏离；当前存在的偏离主要是“验收闭环不足 + 治理深度未完结”，属于可在下一阶段收敛的工程性偏离，而非目标偏离。
