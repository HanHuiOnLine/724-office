# D3 批次计划：澄清恢复路径执行闭环

## 1. 批次目标
让 `resumeFromClarification` 与主路径保持一致：澄清回答后也执行 SQL 并返回真实数据。

## 2. 前置依赖
1. D1 完成（审计摘要）
2. D2 完成（`executionPhase` 可复用）

## 3. 范围边界
### 3.1 允许修改
1. `backend/src/core/agenticEngine.js`（仅 `resumeFromClarification` 相关）

### 3.2 禁止修改
1. `processQuery` 逻辑（D2 已定）
2. SSE/前端（D4 处理）

## 4. 任务分解（WBS）
| 任务ID | 任务内容 | 产出 | 预计工时 |
|---|---|---|---|
| D3-T1 | `resumeFromClarification` 接入执行阶段 | `type='result'` + `data` | 1.0d |
| D3-T2 | 恢复失败后重试执行链路 | 错误链路稳定 | 0.5d |
| D3-T3 | 澄清路径审计对齐 | 真实 rowCount/执行耗时 | 0.5d |
| D3-T4 | 澄清场景手测 + 冒烟 | 运行记录 | 0.5d |

## 5. 详细执行步骤
1. 在 `resumeFromClarification` 中复用 D2 的 `executionPhase`：
   - `verification` 通过即执行 SQL
   - 执行失败触发 `recoveryPhase` 后再执行一次
2. 成功返回统一字段：
   - `type='result'`
   - `data`、`executionTime`
   - 保留 `resumed: true`
3. 审计写入：
   - 成功写真实 `row_count`
   - 失败写真实错误和耗时
4. 验证：
   - 触发澄清 -> 回答 -> 拿到数据
   - `DRY_RUN=true` 时不崩溃

## 6. 验收标准（DoD）
1. 澄清恢复路径成功返回 `type='result'` + `data.rows`。
2. `resumed: true` 保持，兼容上层识别。
3. 审计与主路径语义一致（不再 rowCount=0）。

## 7. 风险与回滚
| 风险 | 回滚/缓解 |
|---|---|
| 与 D2 的执行入参不一致 | 复用同一签名，不自造结构 |
| 澄清历史导致 SQL 不稳定 | 保持 `applyClarificationResult` 原逻辑不改 |
| 出现异常循环恢复 | 限制恢复重试次数，最终返回 error |

## 8. 批次交接要求
完成后新增：`docs/NL2SQL-真实数据批次D3-交接摘要.md`，明确澄清路径返回契约及与 D2 一致性对照。
