# D5 批次计划：测试回归与验收闭环

## 1. 批次目标
补齐“真实数据输出”专项测试，跑通 smoke/阶段回归/真实依赖验证，形成可审计的上线证据。

## 2. 前置依赖
1. D1-D4 全部完成并有交接摘要。

## 3. 范围边界
### 3.1 允许修改
1. `backend/test/phase-data/`（新建）
2. `backend/test/run-all.js`（如需挂接）
3. `backend/package.json`（新增脚本）
4. 验收文档与完工摘要

### 3.2 禁止修改
1. 业务主逻辑（除非发现阻断性缺陷并单独提变更）

## 4. 任务分解（WBS）
| 任务ID | 任务内容 | 产出 | 预计工时 |
|---|---|---|---|
| D5-T1 | 新增主路径数据输出测试 | `test-agentic-execution.js` | 0.5d |
| D5-T2 | 新增澄清恢复数据输出测试 | `test-resume-execution.js` | 0.5d |
| D5-T3 | 新增审计摘要一致性测试 | `test-audit-summary-shape.js` | 0.5d |
| D5-T4 | 接入脚本聚合与 skip 策略 | `package.json` / runner | 0.5d |
| D5-T5 | 执行全量回归并固化报告 | 验收记录与完工摘要 | 1.0d |

## 5. 详细执行步骤
1. 新建 `phase-data` 测试：
   - `test-agentic-execution.js`
   - `test-resume-execution.js`
   - `test-audit-summary-shape.js`
2. 断言重点：
   - 成功返回 `type='result'` + `data`
   - `query_history.row_count` 与返回一致
   - `query_history.result` 仅摘要字段（无 `rows`）
   - `DRY_RUN=true` 行为不回退
3. 依赖策略：
   - 缺 `SR_DATABASE_URL_TEST` / `LLM_API_KEY` 时 skip 并给出明确原因
4. 执行：
   - `npm run test:smoke`
   - `npm run test:phase-data`
   - 真实依赖下跑 `test:phase1`、`test:phase2`、`test:phase-data`

## 6. 验收标准（DoD）
1. `phase-data` 专项测试可重复执行且结果稳定。
2. smoke 0 fail。
3. 真实依赖环境下关键回归通过，形成文本证据。
4. 输出 `完工摘要`，可追踪每批次改动与验收结论。

## 7. 风险与回滚
| 风险 | 回滚/缓解 |
|---|---|
| 真实 LLM 波动导致偶发失败 | 增加重试一次并记录 trace |
| CI 缺真实依赖 | skip 不中断，补线下验收报告 |
| 测试误连生产库 | 强制用 `SR_DATABASE_URL_TEST`，并在脚本前置校验 |

## 8. 最终交付要求
1. `docs/NL2SQL-真实数据输出完工摘要.md`
2. 测试执行结果汇总（命令、通过数、skip 原因）
3. 上线建议与后续跟踪指标（data 命中率、P95、错误码分布）
